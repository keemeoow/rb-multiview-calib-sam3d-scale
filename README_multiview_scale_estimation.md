# 멀티뷰 실루엣 기반 CAD 크기 및 포즈 추정

## 1. 개요

이 파이프라인은 실제 크기가 정의되지 않은 정규화 CAD 메시를 세 대의 RealSense 카메라 영상과 정합하여, 물체의 실제 크기와 월드 좌표계 기준 포즈를 추정한다.

추정 대상은 다음 7개 자유도이다.

- 전역 스케일 `s`: 1-DoF
- 3차원 회전 `R`: 3-DoF
- 3차원 이동 `t`: 3-DoF

따라서 최종적으로 CAD 정점 `V_CAD`에 적용되는 변환은 다음과 같다.

```text
V_world = s · R · V_CAD + t
```

여기서 `s`는 정규화된 CAD 좌표를 실제 길이 단위로 변환하며, `R`과 `t`는 물체를 월드 좌표계에 배치한다.

이 방법의 핵심은 **깊이 영상으로 물체 크기를 직접 측정하지 않는 것**이다. 깊이 영상은 초기 포즈와 초기 스케일 후보를 생성하는 데만 사용하고, 최종 스케일과 포즈는 세 카메라에서 렌더링된 CAD 실루엣이 실제 물체 마스크와 가장 잘 겹치도록 최적화하여 결정한다.

## 2. 핵심 원리

### 2.1 단일 카메라에서 크기를 알 수 없는 이유

한 대의 카메라 영상에서는 물체의 실제 크기와 카메라까지의 거리가 서로 결합되어 있다.

```text
영상에 보이는 크기 ∝ 실제 물체 크기 / 카메라까지의 거리
```

따라서 물체를 `k`배 크게 만들고 카메라에서 `k`배 멀리 배치하면 거의 동일한 2D 투영을 얻을 수 있다. 이를 스케일–깊이 모호성이라고 한다.

단일 카메라에서는 다음 두 상황을 영상만으로 구별하기 어렵다.

- 작은 물체가 카메라 가까이에 있는 경우
- 큰 물체가 카메라 멀리 있는 경우

### 2.2 멀티뷰에서 스케일이 관측 가능한 이유

세 대의 카메라는 서로 다른 위치에서 같은 물체를 관찰한다. 특정 스케일과 위치가 cam0에는 맞더라도 실제 크기와 다르면 cam1과 cam2에서는 투영 위치 또는 실루엣 크기가 맞지 않는다.

따라서 하나의 CAD가 세 카메라 마스크에 동시에 일치하려면, 카메라 사이의 3차원 기하와 일관되는 스케일과 포즈를 가져야 한다.

### 2.3 실제 mm 단위는 어디에서 오는가

실루엣은 영상에서 물체 형상과 투영 위치가 맞는지를 제공하지만, 자체적으로 실제 길이 단위를 포함하지 않는다.

실제 mm 단위는 카메라 외부 파라미터에 포함된 카메라 간 baseline에서 결정된다.

현재 캘리브레이션의 카메라 간 거리는 다음과 같다.

| 카메라 쌍 | Baseline |
|---|---:|
| cam0–cam1 | 952.7 mm |
| cam0–cam2 | 997.5 mm |
| cam1–cam2 | 1052.7 mm |

## 3. 관련 코드

| 파일 | 역할 |
|---|---|
| `Obj_Step3c_cad_scale.py` | 크기 및 Sim(3) 추정 실행용 CLI |
| `_silhouette_fit.py` | CAD 실루엣 렌더링, 손실 계산, Sim(3) 최적화 |

## 4. 입력 데이터

### 4.1 카메라 캡처 데이터

경로:

```text
data/capture_obj/
```

| 파일 | 데이터 차원 | 내용 | 사용 목적 |
|---|---|---|---|
| `cam{0,1,2}_rgb.png` | 2D | 컬러 영상 | 최종 오버레이 및 정성적 검증 |
| `cam{0,1,2}_depth.png` | 2.5D | 픽셀별 깊이값, `uint16`, mm | 초기 3D 점군과 초기값 생성 |
| `cam{0,1,2}_K.txt` | 3×3 행렬 | 카메라 내부 파라미터 | 2D↔3D 투영 및 역투영 |
| `cam{0,1,2}_T_cam_to_world.txt` | 4×4 행렬 | 카메라 외부 파라미터 | 카메라·월드 좌표계 변환 및 metric scale 제공 |

월드 좌표계는 cam0 좌표계로 정의된다.

```text
world = cam0
```

카메라 시리얼은 다음과 같다.

| 카메라 | 시리얼 |
|---|---|
| cam0 | `314522062542` |
| cam1 | `319522062138` |
| cam2 | `912322060991` |

### 4.2 물체 마스크

경로:

```text
data/masks/<obj>/cam{0,1,2}_mask.png   # <obj> = peg, hole, ... (의미 있는 이름)
```

마스크는 SAM2를 이용해 생성한 2D 이진 영상이다.

```text
0   = 배경
255 = 물체
```

마스크는 다음 두 곳에 사용된다.

1. 깊이 영상에서 물체에 해당하는 픽셀만 선택
2. 렌더링된 CAD 실루엣과 IoU 손실 계산

최종 최적화 손실을 직접 구성하기 때문에, 마스크 경계 오차는 크기 추정 오차로 전이될 수 있다.

### 4.3 CAD 메시

경로:

```text
data/meshes/peg.glb
data/meshes/hole.glb
```

CAD는 3D 정점과 삼각형 면으로 구성된 메시이다.

- `peg.glb`: 원기둥 계열 형상
- `hole.glb`: 구멍이 있는 정육면체 형상

CAD는 형상과 축 비율만 제공한다. 실제 mm 크기는 정의되어 있지 않다.

예를 들어 CAD 최대 변의 좌표 길이가 1.0이더라도, 그것이 실제 1 mm인지 50 mm인지는 CAD만으로 알 수 없다. 본 파이프라인은 이 정규화 단위를 실제 mm로 변환하는 전역 스케일 `s`를 추정한다.

## 5. 데이터 차원 구분

### 5.1 2D 데이터

- RGB 이미지
- SAM2 물체 마스크

모든 값이 영상 픽셀 좌표 `(u, v)`에서 정의된다.

### 5.2 2.5D 데이터

- RealSense 깊이 영상

깊이 영상은 2D 픽셀 배열이지만 각 픽셀에 카메라로부터의 거리 `z`가 저장된다. 따라서 완전한 3D 구조가 아니라, 하나의 시점에서 관측된 표면 깊이를 갖는 2.5D 데이터이다.

### 5.3 3D 데이터

- 깊이를 역투영하여 생성한 점군
- 정규화 CAD 메시
- 월드 좌표계에 배치된 CAD
- 카메라 외부 파라미터
- OBB
- 최종 회전, 위치 및 물체 치수

## 6. 전체 처리 흐름

```text
2D RGB ───────────────────────────────────────────────→ 최종 오버레이

2D 마스크 ─┬→ 마스크 내부 깊이 선택 → 3D 초기 점군 ─┐
           └──────────────────────────────────────────┤
                                                     │
2.5D 깊이 ─→ K로 3D 역투영 → T로 월드 변환 ─────────┤
                                                     │
3D CAD ──────────────────────────────────────────────┤
                                                     │
카메라 K, T ─────────────────────────────────────────┘
                         ↓
                 초기 Sim(3) 후보 생성
                         ↓
              CAD에 스케일·회전·이동 적용
                         ↓
            월드의 3D CAD를 각 카메라에 투영
                         ↓
              카메라별 2D CAD 실루엣 생성
                         ↓
          SAM2 마스크와 IoU 기반 손실 계산
                         ↓
                 7-DoF Sim(3) 최적화
                         ↓
      실제 크기 + 3D 회전 + 3D 위치 + IoU + 오버레이
```

## 7. 세부 처리 단계

### 7.1 마스크 침식

마스크 경계에는 물체와 배경이 혼합된 깊이 픽셀이 포함될 수 있다. 이를 줄이기 위해 마스크를 약 3픽셀 침식한 뒤 내부 픽셀만 깊이 역투영에 사용한다.

입력:

- 2D 물체 마스크
- 2.5D 깊이 영상

출력:

- 깊이 초기화에 사용할 침식된 2D 마스크

### 7.2 깊이 영상의 3D 역투영

깊이 픽셀 `(u, v, z)`와 내부 파라미터 `K`를 이용해 카메라 좌표계의 3D 점을 계산한다.

```text
x = (u - cx) · z / fx
y = (v - cy) · z / fy
P_cam = [x, y, z]^T
```

이후 외부 파라미터를 이용해 월드 좌표계로 변환한다.

```text
P_world = T_cam_to_world · P_cam
```

세 카메라에서 생성한 점들을 동일한 월드 좌표계에서 병합한다.

출력:

- 월드 좌표계의 3D 물체 점군

### 7.3 3D 점군 정제

초기 점군에는 배경 누수, 깊이 이상치, 경계 혼합 픽셀이 포함될 수 있다. 다음 순서로 정제한다.

1. 2 mm voxel downsampling
2. 통계적 이상치 제거
3. DBSCAN 군집화
4. 가장 큰 군집 선택

DBSCAN을 적용하지 않으면 소수의 잘못된 점 때문에 초기 OBB가 실제 물체보다 매우 크게 추정될 수 있다.

### 7.4 OBB 기반 초기값 생성

정제된 3D 점군과 CAD 각각에 최소부피 OBB를 계산한다.

OBB의 역할은 다음과 같다.

- 물체 중심을 이용한 초기 이동 `t₀`
- CAD 축과 점군 축을 정렬한 초기 회전 `R₀`
- OBB 변 길이 비율을 이용한 초기 스케일 `s₀`

OBB 축은 순서와 방향에 모호성이 있으므로 24개의 proper rotation 후보를 모두 평가한다.

### 7.5 초기 스케일 후보 선택

OBB로 얻은 스케일 `s₀` 주변의 후보를 평가한다.

```text
0.80 · s₀
0.90 · s₀
1.00 · s₀
1.10 · s₀
```

각 후보에 대해 다음을 수행한다.

1. 스케일 고정
2. ICP로 3D 포즈 보정
3. CAD를 세 카메라 영상에 투영
4. 마스크와 CAD 실루엣의 IoU 손실 계산
5. 가장 낮은 손실의 후보 선택

깊이는 초기 포즈를 제공하지만, 초기 스케일 후보의 최종 선택은 실루엣 손실이 담당한다.

### 7.6 CAD의 3D Sim(3) 변환

CAD 정점에 현재 스케일과 포즈를 적용한다.

```text
V_world = s · R · V_CAD + t
```

이 단계의 입력과 출력은 모두 3D이다.

### 7.7 월드 좌표에서 카메라 좌표로 변환

입력 외부 파라미터는 `T_cam_to_world`이므로, 렌더링할 때는 역행렬을 사용한다.

```python
W_c = np.linalg.inv(T_cam_to_world)
```

```text
V_cam = T_world_to_cam · V_world
```

`_silhouette_fit.py`에서는 각 카메라 View 객체가 생성될 때 이 역행렬을 저장하고, 실루엣을 렌더링할 때마다 사용한다.

### 7.8 3D CAD의 2D 투영

카메라 좌표계의 3D CAD 정점에 내부 파라미터 `K`를 적용한다.

```text
p_h = K · V_cam
u = p_h.x / p_h.z
v = p_h.y / p_h.z
```

투영된 삼각형을 채우면 2D CAD 실루엣이 생성된다.

```text
CAD 정점(3D)
→ 월드 배치(3D)
→ 카메라 좌표(3D)
→ 픽셀 투영(2D)
→ 삼각형 래스터화(2D 실루엣)
```

닫힌 메시에서는 투영된 삼각형의 합집합이 해당 시점에서 보이는 CAD 실루엣이 된다.

래스터화에는 2배 슈퍼샘플링을 사용하여 작은 스케일 변화에도 손실이 반응하도록 한다.

### 7.9 IoU 기반 실루엣 손실

카메라별 실제 마스크 `M_i`와 렌더링된 CAD 실루엣 `M̂_i`의 IoU를 계산한다.

```text
IoU_i = intersection(M_i, M̂_i) / union(M_i, M̂_i)
loss_i = 1 - IoU_i
```

전체 손실은 세 카메라 손실을 평균하거나 합산한 값이다.

```text
L(s, R, t) = mean_i [1 - IoU(M_i, M̂_i)]
```

최적화 변수는 3D이지만, 최적화 품질을 평가하는 관측값은 2D 실루엣이다.

### 7.10 7-DoF 최적화

최적화 변수는 다음과 같다.

```text
(log s, rotvec_x, rotvec_y, rotvec_z, t_x, t_y, t_z)
```

- `log s`: 스케일이 항상 양수가 되도록 함
- `rotvec`: 3차원 회전 표현
- `t`: 월드 좌표계의 3차원 이동

IoU 기반 래스터 손실은 일반적인 의미에서 매끄럽게 미분 가능하지 않으므로 Powell 방법을 사용한다.

반복 과정은 다음과 같다.

```text
변수 갱신
→ CAD 3D 변환
→ 카메라별 2D 투영
→ CAD 실루엣 생성
→ 실제 마스크와 IoU 계산
→ 손실이 감소하도록 다음 변수 선택
```

관측된 함수 평가 횟수 예시는 다음과 같다.

- peg: 654회
- hole: 1065회

## 8. 캘리브레이션 데이터가 사용되는 위치

### 8.1 실루엣 렌더링

`T_cam_to_world`의 역행렬을 사용하여 월드 좌표계의 CAD를 각 카메라 좌표계로 변환한다.

```python
self.W_c = np.linalg.inv(T_cam_to_world)
```

```python
Vw = (s * (R @ V.T)).T + t
Vc = (W_c[:3, :3] @ Vw.T).T + W_c[:3, 3]
uv = (K @ Vc.T).T
uv = uv[:, :2] / uv[:, 2:]
```

이 변환은 최적화 손실을 한 번 계산할 때마다 모든 카메라에 대해 반복된다.

### 8.2 초기 점군 생성

깊이 픽셀을 월드 좌표계로 병합할 때도 `K`와 `T_cam_to_world`가 사용된다.

즉, 캘리브레이션은 다음 두 단계 모두에 관여한다.

- 깊이 기반 초기 3D 점군 생성
- 최종 CAD 실루엣 렌더링 및 스케일 최적화

| Baseline 배율 | 추정 크기 | 평균 IoU |

| 0.90 | 45.8 mm | 0.977 |
| 0.95 | 48.3 mm | 0.977 |
| 1.00 | 50.9 mm | 0.977 |
| 1.05 | 53.4 mm | 0.977 |
| 1.10 | 56.0 mm | 0.977 |

결과적으로 baseline과 추정 크기는 거의 정확히 비례한다.

```text
baseline이 10% 작음 → 추정 크기도 약 10% 작음
baseline이 10% 큼   → 추정 크기도 약 10% 큼
```

그러나 IoU는 0.977로 거의 변하지 않는다.

이 실험은 다음을 보여준다.

1. 영상 실루엣만으로는 metric scale 오류를 검출할 수 없다.
2. 잘못된 baseline을 사용해도 오버레이가 정확해 보일 수 있다.
3. 캘리브레이션의 scale 오차가 크기 추정 오차로 직접 전이된다.
4. 카메라 캘리브레이션 정확도가 크기 추정 정확도의 상한이다.

## 10. 스케일 관측 가능성 확인

최적 포즈를 고정하고 스케일만 변화시켰을 때의 손실은 다음과 같다.

| 스케일 배율 | 추정 치수 | 손실 `1-IoU` |
|---:|---:|---:|
| 0.96 | 48.5 mm | 0.0893 |
| 0.98 | 49.5 mm | 0.0535 |
| 0.99 | 50.0 mm | 0.0399 |
| 1.00 | 50.9 mm | 0.0279 |
| 1.01 | 51.0 mm | 0.0295 |
| 1.04 | 52.6 mm | 0.0647 |

최적 스케일 근처에서 손실이 최소가 되며, 약 ±4%, 즉 약 ±2 mm만 벗어나도 손실이 2~3배 증가한다.

이는 멀티뷰 조건에서 스케일이 실제로 관측 가능하며, 최적화 손실이 올바른 크기 주변에 유효한 최소점을 갖는다는 증거이다.

## 11. 불확실성 평가

마스크 경계 오차가 결과에 미치는 영향을 평가하기 위해 마스크를 1픽셀 침식하거나 팽창한 뒤 전체 추정을 반복한다.

```text
-mask_uncertainty
```

| 대상 | ±1 px 마스크 변화에 따른 크기 변동 | 영상에서 1 px의 실제 길이 |
|---|---:|---:|
| peg | 4.4 mm | 0.79–1.15 mm/px |
| hole | 3.6 mm | 0.93–1.01 mm/px |

peg는 영상에서 약 `33×51 px`로 작게 관측되기 때문에, 마스크 경계 1픽셀의 영향이 상대적으로 크다.

현재 시스템에서 주요 오차원은 다음과 같다.

1. 카메라 baseline과 외부 파라미터 오차
2. SAM2 마스크 경계 오차
3. CAD 형상과 실제 물체 형상의 불일치
4. 깊이 기반 초기값의 품질
5. 낮은 영상 해상도에서 발생하는 래스터 양자화

깊이 데이터는 초기값에만 사용되므로, 최종 결과가 깊이 편향을 그대로 따르지는 않는다. 다만 초기값이 지나치게 잘못되면 지역 최적점이나 잘못된 회전 후보로 수렴할 수 있다.

## 12. 출력 데이터

### 12.1 최적 스케일

```text
s*
```

정규화 CAD 단위를 실제 길이 단위로 변환하는 스칼라이다.

### 12.2 실제 물체 치수

```text
actual_dimension = s* × normalized_CAD_dimension
```

CAD 형상 비율은 고정되어 있으므로 하나의 스케일로 폭, 깊이, 높이가 함께 결정된다.

### 12.3 회전

다음 형식 중 하나로 저장할 수 있다.

- 3×3 회전행렬
- rotation vector
- quaternion

회전은 CAD 좌표계가 월드 좌표계에서 향하는 방향을 나타낸다.

### 12.4 위치

```text
t = [t_x, t_y, t_z]^T
```

단위는 캘리브레이션과 동일한 mm이며, CAD 원점의 월드 좌표계 위치를 나타낸다.

### 12.5 최종 변환

최종 결과는 다음 식으로 표현된다.

```text
V_world = s* · R* · V_CAD + t*
```

저장 시에는 다음 항목을 분리하는 것이 권장된다.

```text
scale
rotation
translation
T_cad_to_world
```

주의할 점은 일반적인 4×4 rigid transform에는 전역 스케일이 포함되지 않는다는 것이다. 따라서 `T_cad_to_world`를 SE(3) 포즈로 저장할 경우 스케일 `s`는 별도 필드로 저장해야 한다.

### 12.6 품질 지표

권장 저장 항목:

```text
IoU_cam0
IoU_cam1
IoU_cam2
IoU_mean
loss_mean
number_of_function_evaluations
convergence_status
```

IoU는 영상 투영의 일치도를 나타내지만, 캘리브레이션의 metric scale 정확도를 단독으로 보장하지 않는다.

### 12.7 시각화 결과

권장 출력:

- 카메라별 RGB + CAD 외곽선 오버레이
- 실제 마스크와 렌더링 실루엣 비교
- 스케일 변화에 따른 손실 곡선
- 마스크 ±1픽셀 불확실성 결과
- 실측값과 추정값 비교 그래프

## 14. 결과 해석 시 주의사항

### 14.1 높은 IoU가 정확한 mm 크기를 보장하지 않는다

카메라 baseline 자체가 잘못된 경우, CAD 크기와 물체 깊이가 함께 잘못 조정되어도 영상 투영은 정확하게 맞을 수 있다.

따라서 다음 두 검증을 분리해야 한다.

- **투영 일치도:** 카메라별 IoU 및 오버레이
- **metric 정확도:** 캘리브레이션 baseline 검증 및 실측 치수 비교

### 14.2 깊이 결과와 최종 크기를 혼동하지 않는다

깊이 점군의 OBB 크기는 최종 크기 결과가 아니다. 깊이는 최적화가 시작할 위치, 방향, 크기 범위를 제공할 뿐이다.

최종 크기는 멀티뷰 실루엣 손실 최소화 결과이다.

### 14.3 CAD 형상 비율이 실제 물체와 일치해야 한다

본 방법은 등방성 스케일 하나만 추정한다. 따라서 실제 물체가 CAD와 다른 가로·세로·높이 비율을 가지면 하나의 스케일만으로는 모든 뷰를 정확하게 맞출 수 없다.

CAD와 실제 물체가 동일한 형상이며 크기만 다른 경우에 가장 적합하다.

### 14.4 대칭 물체의 포즈 모호성

원기둥, 정육면체 등 대칭성이 높은 물체는 서로 다른 회전이 동일하거나 매우 유사한 실루엣을 만들 수 있다.

이 경우 크기는 잘 추정되더라도 회전축 일부는 관측하기 어렵거나 여러 동등 해를 가질 수 있다. 포즈 평가에서는 물체 대칭성을 고려한 회전 오차 지표를 사용해야 한다.

## 15. 캘리브레이션 개선과 크기 정확도의 관계

`Calib_Step3`를 단순 PnP 평균 방식이 아니라 재투영 오차를 직접 최소화하는 번들 조정 방식으로 개선하면 외부 파라미터의 정확도가 높아진다.

합성 검증에서는 외부 파라미터 오차가 다음과 같이 감소하였다.

```text
0.88 mm → 0.55 mm
```

카메라 외부 파라미터 오차는 baseline 오차와 연결되고, baseline 오차는 추정 스케일에 직접 전파된다. 따라서 번들 조정은 단순히 카메라 포즈를 더 정확하게 만드는 것뿐 아니라, 최종 CAD 크기 추정의 정확도 상한을 높이는 역할을 한다.

## 16. 최종 요약

이 파이프라인의 각 데이터 역할은 다음과 같다.

| 데이터 | 핵심 역할 |
|---|---|
| RGB 이미지 | 결과 오버레이 및 정성적 확인 |
| 깊이 이미지 | 초기 3D 점군과 초기 포즈·스케일 후보 생성 |
| SAM2 마스크 | 최종 실루엣 손실을 구성하는 핵심 2D 관측값 |
| 카메라 내부 파라미터 `K` | 깊이 역투영과 CAD 정투영 |
| 카메라 외부 파라미터 `T` | 좌표계 정합, 카메라 baseline 및 mm 단위 제공 |

전체 원리는 다음 한 문장으로 정리할 수 있다.

> 깊이 데이터로 대략적인 3D 초기값을 만들고, 정규화 CAD를 세 카메라에 반복 투영하여 실제 2D 물체 마스크와 가장 잘 겹치는 스케일·회전·이동을 찾으며, 실제 mm 단위는 캘리브레이션된 카메라 baseline에서 결정한다.
